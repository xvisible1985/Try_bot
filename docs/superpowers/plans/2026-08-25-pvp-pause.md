# Пауза PvP (/pvpon, /pvpoff) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two admin-only commands, `/pvpon` and `/pvpoff`, that globally pause/resume the entire PvP subsystem — every PvP command, every PvP button, and every PvP background job refuses/no-ops while paused.

**Architecture:** A single boolean flag (`bot_settings` key-value table, key `pvp_paused`) read fresh from SQLite on every check via `isPvpPaused()`. One identical guard line is inserted as the very first thing in 15 command handlers, at the top of the shared `callback_query` handler, and at the top of 3 background tick functions.

**Tech Stack:** Node.js, `node-telegram-bot-api`, `better-sqlite3`, single file `bot.js`.

---

## Spec

Full design: `docs/superpowers/specs/2026-08-25-pvp-pause-design.md`. Read it before starting — this plan implements it directly.

## Critical shared context — read this before any task

**Re-locate every anchor by searching for the quoted surrounding text, never trust a stated line number** — this file changes with every task in this plan, so line numbers drift task to task.

**The guard is always the exact same one line**, inserted as the literal first line of a handler's body (immediately after the `bot.onText(...)  => {` opening, before anything else — including any existing `const actorLabel = ...` or other setup):

```js
if (isPvpPaused()) return bot.sendMessage(msg.chat.id, '⛔ PvP-бои сейчас приостановлены.', threadOpts(msg)).catch(() => {});
```

For the `callback_query` handler, the guard is different (no `msg`, no `threadOpts` — it's a button click, answered via `answerCallbackQuery`):

```js
if (isPvpPaused()) return bot.answerCallbackQuery(query.id, { text: 'PvP сейчас приостановлен', show_alert: true }).catch(() => {});
```

For the 3 background tick functions, the guard is a bare early return (no message — nothing to reply to, no user action to acknowledge):

```js
if (isPvpPaused()) return;
```

No troll-bot changes anywhere in this plan — troll-bot's own `/fight` system and knockout-mute are untouched.

// Generic key-value settings store — not tied to any one feature, so
// future on/off-style flags can reuse this instead of another ALTER +
// migration. Currently holds only 'pvp_paused' (see /pvpon, /pvpoff,
