# DedoVirus.2026 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a chat "epidemic" game event (DedoVirus.2026) to the Telegram bot: an admin-designated patient zero spreads a virus through coughs, infected users progress through 3 stages with a chance to recover or worsen on each cough, and admin-doctors can apply procedures (`/ukol`, `/klizma`, `/topor`) that boost recovery odds at the cost of a side effect.

**Architecture:** Everything lives in the existing single-file `bot.js`, following this codebase's established convention (every prior feature — `/dimon`, `/fisher`, `/molchun`, etc. — is a SQLite table + `bot.onText` command(s) + a block inside the shared `bot.on('message', ...)` handler). Two new tables (`virus_infections`, `virus_procedures`), a handful of pure helper functions, 7 new commands, one block inserted into the existing message handler, and a `setInterval` for the hourly status broadcast.

**Tech Stack:** Node.js, `node-telegram-bot-api`, `better-sqlite3`. No test framework exists in this repo (`package.json` has no test script, no test files anywhere) — every prior feature was verified by manual Telegram interaction, not automated tests. This plan follows that established practice: pure/deterministic logic gets a throwaway `node -e`/script verification (using Node's built-in `assert`, no new dependency), and everything that depends on live Telegram/DB state is verified manually against the running bot, matching how `/msg` was verified in this same project.

**Anchoring note:** Every insertion point below is given as "find this exact text, replace with...". The anchors are short, unique strings already in `bot.js` (mostly section-header comments) chosen so that later tasks in this plan don't invalidate earlier tasks' anchors — do not use line numbers, they shift as earlier tasks add code.

Full design: `docs/superpowers/specs/2026-07-16-dedovirus-2026-design.md`.

const assert = require('assert');

function rollVirusStageChange(currentStage, improveChance, r) {
  const worsenChance = 0.15;
  if (r < improveChance) {
    if (currentStage <= 1) return { type: 'cured' };
    return { type: 'improve', newStage: currentStage - 1 };
  }
  if (r < improveChance + worsenChance) {
    return { type: 'worsen', newStage: Math.min(3, currentStage + 1) };
  }
  return { type: 'none' };
}

  return arr[Math.floor(Math.random() * arr.length)];

function getVirusRow(userId) {
  return db.prepare('SELECT * FROM virus_infections WHERE user_id = ?').get(userId);

function getActiveVirusProcedureTypes(userId) {
  const now = Math.floor(Date.now() / 1000);
  db.prepare('DELETE FROM virus_procedures WHERE user_id = ? AND expires_at < ?').run(userId, now);
  return db.prepare('SELECT procedure_type FROM virus_procedures WHERE user_id = ?').all(userId).map(r => r.procedure_type);

function getVirusProcedureBonus(userId) {
  return getActiveVirusProcedureTypes(userId).reduce((sum, t) => sum + (VIRUS_PROCEDURES[t]?.bonus || 0), 0);
